# Инструменты Blender для DRONEWORKS

Исследование от 19 ноября 2026. Для станков, конвейера, деталей и других жёстких моделей D2 оставляем **Blender 5.2.4 LTS + bpy + Blender Agent Studio**. Скрипт задаёт размеры, имена и точки вращения по спецификации. Studio быстро показывает, что получилось после сохранения и экспорта. Для D1 нужны ещё два скилла из уже закреплённой версии Studio. Для автоматизации приёмки FBX основным кандидатом остаётся редактор Unity нужной версии с проверкой в режиме batch. [Спецификация моделей](ART_SPEC.md) · [План игры](../../DroneGame/Docs/ROADMAP.md)

## Скиллы на этапах работы

| Когда | Скиллы | Что поручать агенту |
| --- | --- | --- |
| Начало модели | `blender-art-direction-intake`, `blender-modeling-workflow` уже в проекте | Сверить ракурсы, взять размеры из ART_SPEC, собрать блокинг, проверить силуэт и вид с расстояния игрока. Для перспективного концепта использовать совпадающий ракурс, а численные размеры брать из спецификации. |
| Повторяемые детали и материалы | `blender-procedural-workflow` уже в проекте | Генерировать повторяющиеся опоры и крепёж. После появления принятых деталей использовать Asset Browser для общего материала и геометрии. Для `Frame`, `Belt` и других именованных частей сохранить отдельные меши в `EXPORT`. |
| Проверка и исправления | `blender-asset-validation`, `blender-rendering-workflow`, `blender-iterative-refinement`, `blender-mcp-integration` уже в проекте | Измерять экспортированную геометрию в чистом процессе, смотреть фиксированные ракурсы, сравнивать до и после правок. Общий отчёт Studio дополнять проверками бюджета, координат, UV и игровых требований из ART_SPEC. |
| D1, рабочий и анимации | `blender-character-workflow`, `blender-animation-workflow` есть у Studio | Подключить перед D1. Первый покрывает деформации и экспорт рига. Второй покрывает клипы, Mixamo и проверку механического движения. Обе папки с файлами поддержки уже лежат в `.local/studio/plugins/blender-agent-studio/skills/` в проверенной ревизии. |
| Таблички и специальные задачи | `blender-signage-workflow`, `blender-simulation-workflow`, `blender-agent-benchmark` есть у Studio | Для читаемых табличек и декалей, авторских симуляций в Blender и сравнения двух рабочих процессов соответственно. Подключать под подходящий этап. |

Каталог Studio на skills.sh показывает около 1,4 тыс. установок набора на момент проверки. Для нашей мастерской важнее проверенный запуск закреплённой ревизии. Публичная команда `npx skills add ifbars/blender-agent-studio` ставит опубликованный набор и подходит для отдельной оценки обновления. **Другой набор — RobLe3 cc-blender-skill 1.4.** В нём 30 скиллов, в том числе реконструкция по листам, UV-атласы, запекание и визуальное сравнение с источником. В выпуске описано тестирование Blender 5.1.1 через Lab MCP и ahujasid. Для DRONEWORKS стоит взять из него приёмы под конкретный сложный объект, например сверку нескольких ортографических ракурсов грузовика. ## MCP и управление Blender

| Инструмент | Возможности и решение |
| --- | --- |
| **Blender Agent Studio, `blender_workshop`** | Основной помощник для сохранённых сцен. `blender_inspect_asset` даёт JSON с мешами, материалами и треугольниками. `blender_render_evidence` возвращает фиксированные ракурсы и монтаж. `blender_compare_reference` сравнивает проекцию модели с референсом после настройки камеры. Для этих задач достаточно текущей ревизии и Blender, без сборки Rust SceneIR. [Studio](https://github.com/ifBars/blender-agent-studio) |
| **Blender Lab MCP** | Первый кандидат для редактирования открытой сцены вместе с пользователем. Поддерживает Blender 5.1+, запросы к сцене и документации API, снимки и Python в Blender. Живой режим требует расширения и отдельно запущенного MCP-сервера. Имеет смысл проверить на копии сцены, когда понадобится разбираться в несохранённых правках или интерактивно выставлять камеру. [Установка Blender Lab](https://projects.blender.org/lab/blender_mcp/wiki/Setup) · [MCP-сервер](https://projects.blender.org/lab/blender_mcp/src/branch/main/mcp) |
| **Studio Live** | У более новой Studio есть отдельное расширение для просмотра открытой сцены, выбора объекта и передачи снимка с контекстом агенту. Это кандидат, если понадобится именно совместный viewport. В закреплённом сервере мастерской `blender_open_viewport` отсутствует. Проверять отдельно от рабочего MCP. [Studio Live](https://github.com/ifBars/blender-agent-studio/blob/main/docs/live-viewport.md) |
| **MCP for Blender, ahujasid** | Сторонний мост для живой сцены и внешних библиотек или генераторов. Документирует настройку Codex и телеметрию. Интересен при конкретной потребности в его интеграциях, например Sketchfab или стороннем генераторе. [Репозиторий и настройка](https://github.com/ahujasid/mcp-for-blender) |
| **blenderwright, sandraschi/blender-mcp, dcc-mcp-blender** | Запасные варианты. Первый предлагает много типизированных действий в Blender 5.2 и по умолчанию отключает запуск произвольного Python. Второй запускает Blender в фоне и подключает GUI опционально. Третий имеет смысл при работе через общую интеграцию нескольких DCC. Для первого конвейера наши bpy и Studio закрывают те же нужные операции. [blenderwright](https://github.com/HoldMyBeer-gg/blenderwright) · [sandraschi](https://github.com/sandraschi/blender-mcp) · [DCC MCP Blender](https://github.com/dcc-mcp/dcc-mcp-blender) |

В первой итерации достаточно основного MCP и проектного профиля экспорта. При необходимости живой сессии сравнивать один выбранный мост с CLI на одинаковой правке копии модели. Засекать время до пригодного результата, число перезапусков и ручных исправлений. Для обоих вариантов сохранять один и тот же FBX с измерениями и ракурсами. Оставлять новый мост, когда он экономит время на повторяемой операции или закрывает пробел, например доступ к несохранённой сцене. [Методика Studio](https://github.com/ifBars/blender-agent-studio/tree/6ff97fad06d09f5885c941e0bbf3a8f429da3560/plugins/blender-agent-studio/skills/blender-agent-benchmark)

## Готовые решения для моделей

- **Kenney Factory Kit 3.0** — ближайший из найденных наборов к нашей фабрике. В архиве CC0 есть конвейеры, углы, развилки, палеты и ящики в GLB, FBX и OBJ. GLB из набора может ссылаться на внешнюю карту цвета. При открытии сохраняй соседнюю папку `Textures/`. Для наружных корпусов цеха есть City Kit Industrial. Quaternius Ultimate Modular Sci-Fi Pack пригодится как источник модулей интерьера с доступными `.blend`, FBX и OBJ. [Factory Kit](https://kenney.nl/assets/factory-kit) · [Состав архива](../.local/checks/tool-research-01/kenney-pack.json) · [City Kit Industrial](https://kenney.nl/assets/city-kit-industrial) · [Quaternius](https://quaternius.com/packs/ultimatemodularscifi.html)
- **Проверка конвейеров Kenney**. `conveyor.glb` импортировался одним мешем, 196 треугольников и габариты `1,00 × 1,00 × 0,40 м` по X/Y/Z Blender. Средние секции с бортами и без них тоже содержат по одному мешу, обе `0,50 × 1,00 × 0,40 м`. Наш игровой сегмент требует `1,20 × 2,00 × 0,75 м` в осях Blender и отдельных деталей. Kenney годится как быстрый блокинг и для фонового реквизита. Интерактивному сегменту всё равно нужны раздельная лента, стык и собственная настройка UV. [Ракурсы базового модуля](../.local/checks/tool-research-01/kenney-views-textured/contact_sheet.png) · [Метрики базового модуля](../.local/checks/tool-research-01/kenney-conveyor.json) · [Средний модуль](../.local/checks/tool-research-01/kenney-conveyor-long-part-middle.json) · [Средний модуль с бортами](../.local/checks/tool-research-01/kenney-conveyor-long-sides-part-middle.json)
- **Asset Browser и Mio3 UV**. После первых принятых моделей Asset Browser позволит повторно использовать материал палитры, крепёж и общие узлы. Для шаблона достаточно встроенных UV-инструментов. Mio3 UV 2 для Blender 5 добавляет выпрямление и прямоугольную развёртку, что может ускорить ручную работу с лентой и декалями. У `Belt` UV стрелок должны идти вдоль V, под прокрутку в контроллере. PureRef пригодится человеку для просмотра доски референсов поверх Blender. [Blender Asset Browser](https://docs.blender.org/manual/en/5.2/editors/asset_browser.html) · [Mio3 UV](https://github.com/mio3io/mio3_uv) · [PureRef](https://www.pureref.com/handbook/features/) · [Контроллер конвейера](../../DroneGame/Assets/_Project/Scripts/Conveyor/ConveyorSegment.cs)
- **Meshy** годится как источник черновой формы сложного декоративного пропа. Плагин Blender передаёт модели из веб-приложения, а плагин Codex запускает генерацию через CLI. Для генерации из Codex нужен платный тариф, операции расходуют кредиты API. Доступен и отдельный MCP. Meshy DCC Core интересен, если нужны команды для нескольких открытых редакторов, включая Blender и Unity. Для станка и конвейера выгоднее начинать с bpy, где сразу заданы размеры, отдельные узлы и стыки. Время генерации сравнивать с ручной работой до готового FBX, включая чистку, UV и палитру. В CREDITS записать тариф, условия использования и атрибуцию по ART_SPEC. [Плагин Blender](https://docs.meshy.ai/en/webapp/plugins/blender/introduction) · [Плагин Codex](https://docs.meshy.ai/en/webapp/plugins/codex/introduction) · [CLI и MCP](https://docs.meshy.ai/en/api/ai) · [DCC Core](https://docs.meshy.ai/en/webapp/plugins/meshy-dcc/introduction) · [Условия Meshy](https://help.meshy.ai/en/articles/10137554-what-is-the-ownership-of-the-generated-models)
- **Локальная генерация тяжёлой сетки**. TRELLIS.2 по документации требует NVIDIA с 24 ГБ видеопамяти, Hunyuan3D-2.1 указывает до 29 ГБ для формы и текстур. При проверке Windows обнаружила Intel UHD Graphics и виртуальный дисплей. Для текущей машины это не практичная замена bpy или готовым наборам. [TRELLIS.2](https://github.com/microsoft/TRELLIS.2) · [Hunyuan3D-2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)
- **Рабочий D1**. Начать с T-позы по ART_SPEC и Mixamo для гуманоида. Adobe указывает, что разъединённые элементы вроде плавающей головы могут мешать авто-ригу. На тестовом FBX стоит проверить это до отделки, затем проверить присед, сгибы, удержание предмета и клипы в Unity. Для FPV-рук и ручного контроля деформаций есть локальные средства Blender и Rigify. [Adobe Mixamo FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html) · [Blender Rigify](https://docs.blender.org/manual/en/latest/addons/rigging/rigify/index.html)

## Где проверять FBX

- **В Blender**. На существующем пробнике Studio увидела в исходной сцене 48 треугольников, включая 12 у контрольного меша вне `EXPORT`. Из FBX в чистом Blender пришли только `Frame > Belt`, 36 треугольников и габариты `1,20 × 2,00 × 0,75 м` в мировых координатах Blender. Прямой запуск инспекции через CLI и вызов из MCP дали одинаковые JSON-отчёты. Три ракурса и монтаж FBX пришли примерно за 6 секунд в одном локальном прогоне. На них виден розовый материал из-за неразрешённой внешней текстуры после импорта. На ракурсах исходного `.blend` палитра загрузилась. Для проверки экспортированного цвета используй Unity с назначенной общей палитрой. Один пробник подтверждает работу инструментов, преимущество по времени на рабочих моделях ещё предстоит измерить. [Отчёт MCP](../.local/checks/tool-research-01/research-check.json) · [Метрики FBX](../.local/checks/tool-research-01/fbx.json) · [Монтаж FBX](../.local/checks/tool-research-01/views/contact_sheet.png) · [Монтаж исходника](../.local/checks/tool-research-01/source-views/contact_sheet.png)
- **В Unity 6000.3.28f1**. Сначала импорт пробника по [таблице приёмки](BLENDER_WORKFLOW.md#приёмка-fbx-в-unity). После выбора профиля повторяемые проверки можно перенести в C# Editor-скрипт и запустить в batch. При большом потоке моделей настройки импорта можно задавать через `AssetPostprocessor`, ограничив обработку папкой моделей проекта. Редактор нужной версии в проверенных установках не найден, поэтому приёмка остаётся открытой. [Unity ModelImporter](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/modelimporter) · [Unity AssetPostprocessor](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/assetpostprocessor)
- **Автоматизация живого Unity**. В DroneGame уже закреплён Coplay MCP v10.3.0. У Unity сейчас рекомендуемый официальный путь — **Unity CLI + Pipeline**. CLI может обращаться к редактору напрямую или через `unity mcp`. Unity вывела из актуального пути старый сервер внутри `com.unity.ai.assistant`, а команду `unity mcp` продолжает поддерживать. Для интерактивной приёмки разумно сравнить официальный путь с уже закреплённым Coplay в изолированной копии. Официальные Unity Skills полезны для более широких задач в движке. Контракт конкретной модели и измерения FBX остаются в материалах DRONEWORKS. [Coplay в DroneGame](../../DroneGame/Packages/manifest.json) · [Переход на Unity CLI](https://docs.unity.com/en-us/unity-cli/replace-mcp-server-unity-cli) · [Unity Pipeline](https://docs.unity.com/en-us/unity-cli/unity-pipeline/unity-pipeline-package) · [Unity Skills](https://github.com/Unity-Technologies/skills)

## Первый рабочий прогон

Для `SM_ConveyorSegment` применить установленный набор. Собрать два стыкующихся блока по референсу и ART_SPEC, проверить размеры **1,20 × 0,75 × 2,00 м в Unity**, верх ленты **0,60 м**, части `Frame`, `Belt`, `Rail_L`, `Rail_R` и лимит **1 500 треугольников**. Дать ракурсы сверху, с торца и от первого лица. При Unity-приёмке дополнительно проверить ссылку `beltRenderer`, материал стрелок и движение UV в обоих направлениях. Этот прогон даст базу для решения о живом MCP и автоматизации импорта.
